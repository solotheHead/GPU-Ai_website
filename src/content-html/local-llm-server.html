Local LLM server: how much GPU memory do you need?

Running large language models on your own hardware keeps data in-house and makes costs predictable. The first question is always the same: how much GPU memory does the model need? This guide gives you the arithmetic, a sizing table and the hardware that matches each tier — from a single 32GB card to an eight-GPU server.

The two numbers that decide GPU memory

1. Model weights. Multiply the number of parameters by the bytes per parameter of the precision you run:

  • 16-bit (FP16/BF16): about 2 bytes per parameter;
  • 8-bit (FP8/INT8): about 1 byte per parameter;
  • 4-bit (for example GPTQ, AWQ or GGUF Q4 formats): about 0.5–0.6 bytes per parameter.

A 70-billion-parameter model therefore needs about 140GB at 16-bit, 70GB at 8-bit and 35–42GB at 4-bit, before anything else is loaded.

2. Context (the KV cache). Every token in the context window keeps keys and values in GPU memory, for every user served at the same time. For a 70B model of the Llama 3 type with grouped-query attention, this is roughly 0.3MB per token at 16-bit — about 10GB for one 32,000-token conversation. Ten users with long contexts can need more memory for the KV cache than for the model itself.

Add a margin of 10–20% for the runtime, activations and memory fragmentation.

Memory decides what fits; bandwidth decides how fast

For a single user, the speed of text generation is limited mainly by memory bandwidth, because the weights are read for every token. That is why an H200 NVL (4.8 TB/s) generates faster than an RTX PRO 6000 (1.6 TB/s), and why lower precision is also faster: a 4-bit model has a quarter of the bytes to read of a 16-bit one. For many users at once, batching makes compute and the KV cache the limits, and serving software such as vLLM or SGLang uses the GPU far more efficiently than single-user tools.

Planning checklist

  1. Pick the models

    List the models you will run now and in the next year, at the precision you accept for quality.

  2. Estimate the users and context

    Concurrent users and context length set the KV cache. Long documents and agents need much more than chat.

  3. Add headroom

    New models tend to be larger. A server with free slots lets you add GPUs later in the same platform.

  4. Plan the room

    GPU servers draw kilowatts and are loud. Decide between your premises and colocation early.

Frequently asked questions

Is 4-bit quantisation good enough?

For many chat and assistant tasks, well-made 4-bit versions of large models perform close to the original, and a larger model at 4-bit often beats a smaller model at 16-bit. For precise tasks such as code or structured extraction, test 8-bit as well before deciding.

Can I combine different GPUs in one server?

Technically yes, but splitting one model across different GPU models is limited by the slowest card and the smallest memory. Identical GPUs are simpler to run and to scale.

Do I need server CPUs and ECC memory?

For a production server, yes: server platforms give enough PCIe lanes for several GPUs at full bandwidth, plenty of memory channels and ECC memory for reliability.
